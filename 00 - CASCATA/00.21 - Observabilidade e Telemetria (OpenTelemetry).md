## 1. Os Três Pilares da Observabilidade no Enlace

A observabilidade não é adicionada a posteriori; ela nasce acoplada à arquitetura através do padrão aberto **OpenTelemetry (OTel)**:

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                       PILARES DE TELEMETRIA DO SISTEMA                      │
├─────────────────────────────────────────────────────────────────────────────┤
│  1. LOGS ESTRUTURADOS EM JSON COM SCRUBBING AUTOMÁTICO DE PII               │
│     Registram eventos de negócio com formato uniforme, higienizando senhas, │
│     CPFs, cartões e nomes civis antes de qualquer saída de console ou disco.│
│                                                                             │
│  2. MÉTRICAS QUANTITATIVAS EM TEMPO REAL (PROMETHEUS)                       │
│     Contadores, medidores e histogramas de latência para validação contínua │
│     dos SLOs estabelecidos nos requisitos não-funcionais.                   │
│                                                                             │
│  3. RASTREAMENTO DISTRIBUÍDO (DISTRIBUTED TRACING)                          │
│     Propagação de 'Trace-ID' desde o clique na UI do cliente até o banco de │
│     dados e chamadas externas ao gateway de pagamento.                      │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 2. Padrão Estruturado de Logs e Máscara Sanitizadora

Todo log gerado pela aplicação adota a seguinte estrutura JSON:

```json
{
  "timestamp": "2026-09-25T11:40:00.123Z",
  "level": "INFO",
  "service": "enlace-core",
  "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736",
  "span_id": "00f067aa0ba902b7",
  "action": "ORDER_PIX_SPLIT_COMPLETED",
  "actor": {
    "account_id": "usr_8291a9b2",
    "role": "CLIENT",
    "pseudonym": "Cliente_4829"
  },
  "resource": {
    "order_id": "ord_99214",
    "provider_id": "prv_11234",
    "total_cents": 5000,
    "split_provider_cents": 4250,
    "split_platform_cents": 750
  },
  "http": {
    "method": "POST",
    "route": "/api/v1/orders/checkout",
    "status_code": 200,
    "duration_ms": 48.2
  }
}
```

### Regra de Ouro do Log Sanitizer:
Um middleware de logging intercepta todas as mensagens e aplica substituição por expressões regulares para mascarar dados sensíveis:
- Padrões de CPF são substituídos por `[CPF_PROTEGIDO]`;
- Padrões de e-mail têm o nome do usuário ofuscado (`e***o@dominio.com`);
- Chaves Pix de telefone têm o meio do número mascarado (`(68) 9****-1234`);
- Parâmetros com nome `password`, `token`, `secret`, `cvv` têm seus valores substituídos por `[REDACTED]`.

## 3. Catálogo de Métricas Críticas (SLOs Operacionais)

| Métrica Prometheus | Tipo | Propósito | Alerta Crítico |
| :--- | :--- | :--- | :--- |
| `enlace_http_request_duration_seconds` | Histograma | Mede latência P50, P95 e P99 de todas as rotas. | $P_{95} > 120\text{ms}$ por 5 min. |
| `enlace_search_latency_seconds` | Histograma | Mede tempo de resposta de busca com filtros de acessibilidade. | $P_{95} > 80\text{ms}$ por 3 min. |
| `enlace_http_requests_total` | Contador | Volume de requisições por rota e código HTTP. | Taxa de HTTP 5xx $> 0.05\%$. |
| `enlace_payment_split_failures_total` | Contador | Falhas no split automático Pix com o gateway. | $> 0$ falhas no período de 15 min. |
| `enlace_verification_rejections_total`| Contador | Quantidade de cadastros barrados por idade $< 18$. | Anomalia de picos (tentativa de ataque). |
| `enlace_media_queue_depth` | Medidor | Fila de processamento de vídeos/fotos pendentes no Redis. | $> 100$ tarefas na fila por mais de 10 min. |
| `enlace_active_db_connections` | Medidor | Conexões ativas no pool do PostgreSQL. | $> 80\%$ da capacidade máxima do pool. |
