A transição entre as fases do ciclo de desenvolvimento exige cumprimento estrito dos seguintes portões de aprovação:

```text
[Gate 0: Requisitos & Domínio] ──(Aprovado)──> [Gate 1: Diagramas & Arquitetura]
                                                         │
                                                     (Aprovado)
                                                         │
                                                         ▼
[Gate 3: QA & Testes] <──(Aprovado)── [Gate 2: Schemas de Dados & Contratos]
        │

        │
        ▼
[Gate 4: Acessibilidade & LGPD] ──(Aprovado)──> [Gate 5: Go-Live Piloto Acre]
```

## 2. Estratégia de Implantação: Blue-Green Deployment com Zero-Downtime

Para manter disponibilidade $\ge 99.9\%$, a plataforma adota a técnica de **Implantação Azul-Verde (Blue-Green Deployment)**:

```text
                        ┌────────────────────────┐
                        │      Cloudflare CDN    │
                        └───────────┬────────────┘
                                    │
                                    ▼
                        ┌────────────────────────┐
                        │    Load Balancer       │
                        └─────┬────────────┬─────┘
                              │            │
             (100% Tráfego)   │            │  (Tráfego de Homologação 0%)
                              ▼            ▼
                     ┌──────────────┐ ┌──────────────┐
                     │  Versão BLUE │ │ Versão GREEN │
                     │  (Produção)  │ │  (Novo Build)│
                     └──────┬───────┘ └──────┬───────┘
                            │                │
                            └───────┬────────┘
                                    │
                                    ▼
                        ┌────────────────────────┐
                        │  PostgreSQL Cluster    │
                        │  (Migração Compatível) │
                        └────────────────────────┘
```

1. **Migrações de Banco com Compatibilidade Reversa (Expand and Contract):**
   - As alterações de DDL no PostgreSQL nunca removem colunas de imediato. A primeira fase adiciona campos de forma compatível; a versão antiga continua operando; a nova versão assume; e a remoção de campos legados ocorre na fase seguinte.
2. **Gatilhos Automáticos de Rollback (Circuit Breakers):**
   - Se após a virada do tráfego a taxa de erros HTTP 5xx ultrapassar $0.1\%$ ou a latência P95 ultrapassar $200\text{ms}$ por mais de 60 segundos, o Load Balancer reverte instantaneamente $100\%$ do tráfego para a versão Blue estável.
3. **Observabilidade em Tempo Real:**
   - Métricas de APM via Prometheus/Grafana e rastreamento distribuído via OpenTelemetry monitoram a saúde da aplicação antes, durante e após cada release.
