## 1. Escopo Positivo (Incluso no Projeto)

O ecossistema **Enlace** compreende as seguintes fronteiras funcionais e técnicas:

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                         FRONTEIRAS DO SISTEMA ENLACE                        │
├─────────────────────────────────────────────────────────────────────────────┤
│  1. GESTÃO DE IDENTIDADE E PERFIS                                           │
│     ├── Cadastro e autenticação segura (MFA opcional, OAuth2 / OIDC)        │
│     ├── Verificação escalonada de identidade (+18 civil, liveness biométrico)│
│     ├── Perfil público do prestador com nome artístico, fotos e tarifas     │
│     └── Pseudônimo público estrito para clientes ("Cliente_XXXX")           │
│                                                                             │
│  2. ACESSIBILIDADE ESTRUTURAL NO DOMÍNIO                                    │
│     ├── Cadastro de adaptações oferecidas pelo prestador (Libras, mobilidade)│
│     ├── Perfil de requisitos funcionais do cliente                          │
│     ├── Motor de busca e recomendação por compatibilidade de acessibilidade │
│     └── Interface web e mobile em estrita conformidade WCAG 2.2 Nível AA/AAA│
│                                                                             │
│  3. LOCALIZAÇÃO E GEORREFERENCIAMENTO PROTEGIDO                             │
│     ├── Filtro por Estado (UF), Município, Bairro e Raio aproximado         │
│     └── Camada de ofuscação (coordenadas e endereço exato NUNCA públicos)   │
│                                                                             │
│  4. SOLICITAÇÃO E CONEXÃO EXTERNA SEM FRICÇÃO                               │
│     ├── Cartão estruturado de solicitação de horário/serviço                │
│     └── Redirecionamento transparente para canais externos autorizados      │
│         (WhatsApp, Telegram, Telefone) sem intermediários coercitivos       │
│                                                                             │
│  5. MONETIZAÇÃO HÍBRIDA INTEGRADA                                           │
│     ├── Gestão de assinaturas de visibilidade para prestadores (Planos)     │
│     ├── Paywall de mídias digitais privadas (fotos/vídeos avulsos e feeds)  │
│     ├── Split financeiro automático entre plataforma e prestador via Pix    │
│     └── Marca d'água esteganográfica para proteção contra vazamentos        │
│                                                                             │
│  6. REPUTAÇÃO E SEGURANÇA COMUNITÁRIA                                       │
│     ├── Avaliação bilateral pública (cordialidade, pontualidade, respeito)  │
│     ├── Avaliação confidencial de segurança (score invisível de risco)      │
│     ├── Mecanismo de bloqueio mútuo preventivo                              │
│     └── Moderação reativa baseada em denúncias com suspensão temporária     │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 2. Escopo Negativo (Expressamente Excluído / Não-Escopo)

Para assegurar foco, conformidade legal, viabilidade operacional e respeito às decisões do produto, os seguintes itens **NÃO** fazem parte do escopo do Enlace:

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                          NÃO-ESCOPO DELIBERADO                              │
├─────────────────────────────────────────────────────────────────────────────┤
│  [X] Chat interno de mensageria instantânea no MVP (decisão B: contato      │
│      externo direto; evita passivo de armazenamento e burocracia desnecessária)│
│                                                                             │
│  [X] Botão de pânico de emergência ou integração policial direta (decisão   │
│      do produto: proteção física pública é dever do Estado; o sistema foca  │
│      em prevenção, verificação de identidade e blindagem de dados)          │
│                                                                             │
│  [X] Intermediação financeira obrigatória de encontros presenciais          │
│      (prestadores e clientes têm autonomia para acertar valores presenciais)│
│                                                                             │
│  [X] Equipe permanente de moderação humana em tempo real (substituída por    │
│      validações algorítmicas estritas de upload e denúncia reativa)         │
│                                                                             │
│  [X] Exposição pública de dados civis, endereços de atendimento ou CPF      │
│                                                                             │
│  [X] Suporte a transações de menores de 18 anos ou conteúdos não-consensuais│
│      (tolerância zero; bloqueio e cooperação legal conforme legislação)     │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 3. Matriz de Fronteiras de Integração Externa

| Sistema Externo | Tipo de Integração | Responsabilidade |
| :--- | :--- | :--- |
| **Gateway de Pagamento (PIX / Cartão)** | API REST / Webhooks | Processamento financeiro seguro, split automático e tokenização PCI-DSS. |
| **Provedor de KYC / Liveness** | SDK / API Server-to-Server | Validação biométrica de documentos oficiais (RG/CNH) e prova de vida +18. |
| **Base de Perceptual Hash (Anti-CSAM)** | Libs criptográficas / API | Análise de hashes conhecidos no momento do upload de qualquer mídia. |
| **Canais Externos de Mensageria** | Deep Links (`wa.me`, `t.me`) | Redirecionamento seguro para o canal preferencial do prestador. |
| **Armazenamento de Objetos (S3 / MinIO)** | SDK com URLs Pré-assinadas | Guarda isolada de mídias criptografadas com CDN de baixa latência. |
