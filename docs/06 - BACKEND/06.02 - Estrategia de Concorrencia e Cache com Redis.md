## 1. Topologia e Papéis do Redis 7+

Na Plataforma Enlace, o Redis opera em cluster com persistência híbrida (AOF a cada segundo + RDB a cada 15 minutos), servindo a três funções fundamentais:
1. **Cache de Catálogo de Vitrine (Read-Through):** Alívio de queries espaciais PostGIS repetitivas.
2. **Rate Limiting Anti-Scraping:** Janelas deslizantes por IP e por token para proteção de dados de acompanhantes.
3. **Bloqueio Distribuído (Distributed Lock via Redlock):** Prevenção de double-spend em checkouts Pix e Webhooks concorrentes.

---

## 2. Padrões de Chaveamento e TTLs

Todas as chaves no Redis seguem a convenção com namespace tipado: `enlace:{contexto}:{entidade}:{identificador}`:

| Namespace | Exemplo de Chave | TTL | Propósito |
| :--- | :--- | :--- | :--- |
| `catalog:search` | `enlace:catalog:search:AC:RioBranco:hash` | 60 segundos | Cache de busca regional de vitrine |
| `ratelimit:ip` | `enlace:ratelimit:ip:192.168.1.1` | 60 segundos | Janela de requisições (máximo 60 req/min) |
| `idempotency:pix`| `enlace:lock:order:checkout:ord_123` | 10 segundos | Lock distribuído durante liquidação |
| `session:revoked`| `enlace:auth:revoked:acc_456` | 24 horas | Lista de tokens JWT revogados precocemente |

## 3. Algoritmo de Bloqueio Distribuído (Redlock)

Para garantir que um webhook do gateway Pix recebido simultaneamente em múltiplos nós não credite duas vezes o mesmo repasse no livro-razão (`payout_ledger`):

```typescript
// Fluxo canônico do Distributed Lock
const lockKey = `enlace:lock:order:${orderId}`;
const acquired = await redis.set(lockKey, workerId, 'NX', 'PX', 5000);

if (!acquired) {
  // Outro worker está processando a liquidação deste pedido
  return Result.fail('Liquidação em processamento concorrente.');
}

try {
  await ProcessPixWebhookUseCase.execute(dto);
} finally {
  // Liberação segura apenas se o worker ainda for o dono do lock
  await releaseLock(lockKey, workerId);
}
```
