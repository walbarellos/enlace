## 1. Fluxo de Autenticação com Rotação de Tokens e Pseudônimo

O diagrama a seguir descreve o protocolo de emissão e renovação de credenciais, assegurando sessões protegidas sem exposição de dados pessoais:

```mermaid
sequenceDiagram
    autonumber
    actor Cliente as Usuário (Cliente)
    participant Web as Aplicação Web (Next.js)
    participant AuthAPI as Módulo de Identidade & Acesso
    participant Redis as Redis Session Store
    participant DB as PostgreSQL (Accounts)

    Cliente->>Web: Informa e-mail/celular e senha
    Web->>AuthAPI: POST /api/v1/auth/login {identifier, password}
    AuthAPI->>DB: Busca conta e hash de senha (Argon2id)
    AuthAPI->>AuthAPI: Valida hash de senha e status da conta
    
    alt Conta é de Cliente
        AuthAPI->>DB: Recupera Pseudônimo (ex: "Cliente_3914")
    else Conta é de Acompanhante
        AuthAPI->>DB: Recupera Nome Artístico (ex: "Lorena")
    end

    AuthAPI->>AuthAPI: Gera Access Token JWT (Expira em 15 min)<br/>Payload: {sub: accountId, role, pseudonym}
    AuthAPI->>AuthAPI: Gera Refresh Token Criptográfico (UUID v4)
    AuthAPI->>Redis: Armazena Refresh Token com TTL de 30 dias
    
    AuthAPI-->>Web: Retorna 200 OK<br/>• Body: {accessToken, user: {pseudonym, role}}<br/>• Set-Cookie: refreshToken (HttpOnly, Secure, SameSite=Strict)
    Web-->>Cliente: Interface autenticada exibindo apenas o Pseudônimo

    Note over Web,AuthAPI: Renovação Silenciosa de Sessão (Sliding Window)
    Web->>AuthAPI: POST /api/v1/auth/refresh (Cookie: refreshToken)
    AuthAPI->>Redis: Valida e consome Refresh Token antigo (Revogação)
    AuthAPI->>Redis: Emite novo Refresh Token rotativo
    AuthAPI-->>Web: Retorna novo Access Token e novo Cookie rotacionado
```

## 2. Algoritmo de Geração de Pseudônimo Compulsório

Para garantir que o cliente nunca seja identificado por seus dados reais, o sistema executa a seguinte rotina determinística e opaca no momento do registro:

```text
Entrada: AccountID (UUID v4) + Pepper Secreto da Aplicação
    │
    ▼
Função de Dispersão: HMAC-SHA256(AccountID, SystemPepper)
    │
    ▼
Extração Numérica: InteiroDerivado = BytesExtraídos % 9000 + 1000
    │
    ▼
Pseudônimo Gerado: "Cliente_" + InteiroDerivado (ex: "Cliente_4829")
```

- **Propriedades do Algoritmo:**
  - **Irreversibilidade Pública:** É matematicamente impossível para outro usuário deduzir o e-mail ou nome civil do cliente a partir do pseudônimo `Cliente_4829`.
  - **Consistência de Apelido:** O cliente preserva a mesma identidade pública anônima em todas as suas avaliações e solicitações na plataforma.
