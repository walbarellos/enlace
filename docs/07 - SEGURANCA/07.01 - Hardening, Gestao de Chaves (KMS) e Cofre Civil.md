## 1. Arquitetura do Cofre Civil Criptografado (`vault_civil`)

O esquema de banco de dados `vault_civil` é fisicamente e logicamente segregado do esquema operacional `public`. Ele armazena exclusivamente:
* Nome civil e documentos oficiais (RG/CPF) de acompanhantes;
* Imagens de selfies biométricas (+18 liveness);
* Dados bancários e chaves Pix brutas para repasse.

### 1.1. Criptografia Envelope (Envelope Encryption) com AES-256-GCM

Nenhum dado civil é gravado em texto claro:
1. **Master Key (KEK - Key Encryption Key):** Armazenada em Hardware Security Module (HSM) ou serviço de KMS (Key Management Service) com rotação anual automática.
2. **Data Key (DEK - Data Encryption Key):** Gerada aleatoriamente por registro para criptografar o payload com AES-256-GCM (criptografia autenticada).
3. **Associação Criptográfica (AAD):** O próprio `account_id` é injetado como *Additional Authenticated Data*, impedindo que um ciphertext criptografado de um usuário seja transplantado para o registro de outro.

## 2. Row-Level Security (RLS) Estrita

O acesso ao cofre é bloqueado para consultas normais de aplicação:

```sql
-- RLS compulsória ativada
ALTER TABLE vault_civil.identities ENABLE ROW LEVEL SECURITY;

-- Política de isolamento: Nenhuma leitura sem contexto de auditoria e credencial de oficial de conformidade
CREATE POLICY p_vault_identities_compliance_strict ON vault_civil.identities
FOR SELECT TO role_compliance_officer
USING (
  current_setting('app.compliance_audit_reason', true) IS NOT NULL
  AND current_setting('app.compliance_authorized_user', true) IS NOT NULL
);
```

## 3. Blind Indexing para Busca de Documentos

Para permitir verificação de duplicidade de CPF ou RG sem descriptografar o cofre em massa, utiliza-se a técnica de **Blind Index**:
* $\text{BlindIndex} = \text{HMAC-SHA256}(\text{Documento}, \text{StaticSalt}_{\text{secret}})$.
* Permite consulta exata (`WHERE cpf_blind_index = $1`) sem vazar os números reais em índices de banco de dados ou logs de query planner.
