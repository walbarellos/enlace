## 1. Topologia Modular e Regras de Dependência

A **Plataforma Enlace** é implementada como um **Monólito Modular** composto por 13 *Bounded Contexts* independentes. A comunicação inter-módulos respeita as seguintes restrições:

1. **Invocação Direta Restrita:** Um módulo pode invocar outro apenas através de sua **Interface Pública de Aplicação** (Porta de Entrada), sendo estritamente proibido importar entidades de domínio ou repositórios de outro módulo.
2. **Comunicação Preferencial por Eventos:** Efeitos colaterais entre domínios (ex: liberar conteúdo após pagamento) são mediados pelo *In-Process Event Bus*.
3. **Proibição de Dependências Circulares:** A matriz de dependência é estritamente acíclica (DAG).

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                       MATRIZ DE DEPENDÊNCIA DOS MÓDULOS                     │
├─────────────────────────────────────────────────────────────────────────────┤
│  Módulo                │ Depende de (via Interface Pública / Eventos)        │
├────────────────────────┼────────────────────────────────────────────────────┤
│  Identity              │ (Nenhum módulo de negócio; base do sistema)        │
│  Profiles              │ Identity                                           │
│  Accessibility         │ (Nenhum módulo; provê serviços de matching)        │
│  Availability          │ Profiles                                           │
│  Discovery             │ Profiles, Accessibility, Subscriptions             │
│  Requests              │ Identity, Profiles, Accessibility, TrustSafety     │
│  Content               │ Identity, Profiles                                 │
│  Commerce              │ Identity, Content, Subscriptions                   │
│  Subscriptions         │ Identity, Profiles                                 │
│  Reviews               │ Identity, Profiles, Requests, TrustSafety          │
│  TrustSafety           │ Identity, Profiles                                 │
│  Notifications         │ Identity (escuta eventos de todos os módulos)      │
│  Administration        │ Todos os módulos (leitura/auditoria sob RBAC estrito)│
└─────────────────────────────────────────────────────────────────────────────┘
```

## 2. Contratos de Interface entre Módulos (Service Contracts)

### 2.1 Interface Pública do Módulo de Identidade (`IIdentityModule`)
```typescript
export interface IIdentityModule {
  getAccountById(accountId: string): Promise<AccountDTO | null>;
  verifySession(token: string): Promise<SessionContext>;
  getPseudonymByAccountId(accountId: string): Promise<string>;
  assertVerificationLevel(accountId: string, requiredLevel: VerificationLevel): Promise<boolean>;
}
```

### 2.2 Interface Pública do Módulo de Acessibilidade (`IAccessibilityModule`)
```typescript
export interface IAccessibilityModule {
  calculateMatchScore(
    clientPreferences: AccessibilityRequirementDTO[],
    providerOfferings: AccessibilityAccommodationDTO[]
  ): MatchResultDTO;
  
  validateAccommodationCode(code: string): boolean;
  getRecognizedTaxonomy(): Promise<AccessibilityTaxonomyDTO[]>;
}
```

### 2.3 Interface Pública do Módulo de Conteúdo e Entitlements (`IContentModule`)
```typescript
export interface IContentModule {
  hasActiveEntitlement(accountId: string, contentAssetId: string): Promise<boolean>;
  grantEntitlement(command: GrantEntitlementCommand): Promise<EntitlementDTO>;
  getPlaybackManifest(contentAssetId: string, buyerPseudonym: string): Promise<SignedPlaybackDTO>;
}
```

### 2.4 Interface Pública do Módulo de Confiança e Segurança (`ITrustSafetyModule`)
```typescript
export interface ITrustSafetyModule {
  isProfileQuarantined(providerId: string): Promise<boolean>;
  recordConfidentialAlert(command: IngestSafetyAlertCommand): Promise<void>;
  areMutuallyBlocked(userAId: string, userBId: string): Promise<boolean>;
  calculateRiskScore(accountId: string): Promise<RiskScoreDTO>;
}
```

## 3. Resumo dos Bounded Contexts

1. **`Identity`**: Responsável por credenciais, tokens JWT, MFA e derivação matemática do pseudônimo público.
2. **`Profiles`**: Gerencia a vitrine artística pública do acompanhante (biografia, tabela de tarifas, fotos públicas aprovadas).
3. **`Accessibility`**: Mantém a taxonomia estruturada de 5 dimensões e executa o motor vetorial de compatibilidade funcional.
4. **`Availability`**: Controla os turnos de atendimento semanal e o status dinâmico "Disponível agora".
5. **`Discovery`**: Executa a busca georreferenciada com ofuscação de coordenadas (raio difuso 500m) e ranking ponderado.
6. **`Requests`**: Monta o cartão padronizado de solicitação e gera o deep link para contato direto externo.
7. **`Content`**: Administra fotos e vídeos privados, paywall unitário e ciclo de vida de *Entitlements*.
8. **`Commerce`**: Orquestra ordens financeiras, integração de checkout Pix e cálculo de split automático 85/15.
9. **`Subscriptions`**: Gerencia planos de destaque (Bronze, Prata, Ouro, Diamante) e multiplicadores de relevância.
10. **`Reviews`**: Processa a avaliação pública bilateral com janela cega (*Double-Blind*) de 7 dias.
11. **`TrustSafety`**: Recebe alertas privados de conduta, processa o motor bayesiano e aplica quarentena automática.
12. **`Notifications`**: Despacha comunicações transacionais críticas (e-mail, SMS, alertas de expiração) via mensageria assíncrona.
13. **`Administration`**: Fornece ferramentas de conformidade judicial e auditoria de quarentenas sob privilégio mínimo.
